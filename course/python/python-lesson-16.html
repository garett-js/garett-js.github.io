Урок 16. Python ООП. Часть 2

Принципы ООП

Абстракция
Абстракция - это выделение только важных характеристик объекта.
Например, у телефона основные свойства — это возможность звонить и принимать звонки. Его внутреннее устройство нас не интересует.

Наследование
Наследование позволяет одному классу (дочернему) перенимать свойства и методы другого класса (родительского).
Например, все смартфоны — это телефоны, но они могут обладать дополнительными функциями, такими как запуск приложений.

Инкапсуляция
Инкапсуляция — это сокрытие внутренней реализации объекта.
Внешний мир взаимодействует с объектом через публичные методы, а не напрямую с его внутренними данными.

Полиморфизм
Полиморфизм позволяет одному и тому же методу работать по-разному в зависимости от объекта, который его вызывает.
Например, разные модели телефонов могут совершать вызов по-разному.

Абстракция

Продолжим рассматривать все эти принципы на примере RPG персонажей. Начнем с создания абстрактного класса AbstractCharacter

  1. Создадим папку character
  2. Добавим файл character.py , где будут находится только классы
  3. Добавим файл main.py , где будет находится главная функция main

В RPG мире все персонажи обладают базовыми способностями: атаковать и защищаться. Имеют базовые характеристики имя, количество жизней, уровень.

Вместо того чтобы прописывать эти способности каждому типу (рыцари, маги, лучники), мы выделяем общую "абстракцию" — базовый класс, описывающий основные функции любого персонажа.

Пропишем все классы внутри файла character.py

Python
from abc import ABC, abstractmethod

class AbstractCharacter(ABC):
    def __init__(self, name: str, hp: int, level: int):
        self.name = name
        self.hp = hp
        self.level = level
    
    @abstractmethod
    def attack(self) -> None:
        pass
    
    @abstractmethod
    def defend(self) -> None:
        pass

Абстрактный класс: Это шаблон, который задаёт базовые характеристики и поведение для всех наследников, но не может быть создан напрямую.

Методы без тела: Абстрактный метод (например, attack) будет реализован позже, в классах-наследниках.

Особенности Python:

  1. Модуль abc: В Python для создания абстрактных классов используется модуль abc (Abstract Base Classes)
  2. ABC: Класс должен наследоваться от ABC чтобы стать абстрактным
  3. @abstractmethod: Декоратор указывает, что метод является абстрактным и должен быть переопределён в дочерних классах
  4. Аннотации типов: -> None указывает, что метод ничего не возвращает

Теперь, любой персонаж может быть создан на основе этой абстракции

Наследование

  • Родительским классом с базовыми характеристиками общими для всех персонажей будет абстрактный класс персонажа AbstractCharacter
  • От него унаследуют характеристики два других класса: Воин и Маг
  • Воин и Маг будут иметь полностью все характеристики своего родителя + свои уникальные характеристики.
  • У Мага, в свою очередь, тоже есть два наследника: Темный маг и Белый маг
  • Темный маг и Белый маг будут иметь полностью все характеристики своего родителя мага + полностью все характеристики родителя мага AbstractCharacter + свои уникальные характеристики.

Используем синтаксис class Child(Parent): чтобы унаследовать характеристики от другого класса

Python
# Класс Warrior наследуется от AbstractCharacter
class Warrior(AbstractCharacter):
    def __init__(self, name: str, hp: int, level: int, strength: int):
        super().__init__(name, hp, level)  # Вызов конструктора родителя
        self.strength = strength  # Сила воина

    # Переопределяем метод атаки
    def attack(self) -> None:
        print(f"Воин {self.name} атакует врага с силой {self.strength}!")

    # Переопределяем метод защиты
    def defend(self) -> None:
        print(f"Воин {self.name} ставит щит и защищается!")
  1. class Warrior(AbstractCharacter): означает что Warrior унаследует все характеристики AbstractCharacter
  2. self.strength = strength Уникальное свойство для класса Warrior
  3. super().__init__(name, hp, level) вызов конструктора при наследовании. Обязательно нужно сначала вызывать конструктор родителя через super(), потом инициализировать свойства наследника. Чтобы сначала инициализировать свойства родительского класса, а потом уже класса потомка.
  4. def attack(self) -> None: переопределяем родительские методы, т.е. берем методы родителя с тем же названием, но переделываем внутренний функционал, меняем форму (вид полиморфизма)

Особенности Python в наследовании:

  1. super(): Функция для вызова методов родительского класса. В Python можно вызывать super() без параметров
  2. Множественное наследование: Python поддерживает наследование от нескольких классов одновременно: class Child(Parent1, Parent2):
  3. MRO (Method Resolution Order): Python определяет порядок поиска методов в иерархии наследования

object
У каждого объекта в языке программирования Python, существует, один главный, но по умолчанию невидимый, родительский класс object
От класса object наследуются некоторые общие методы, такие как __hash__ и __str__

  • __str__ — это специальный метод, который возвращает строковое представление объекта.

# Класс Mage наследуется от AbstractCharacter
class Mage(AbstractCharacter):
    def __init__(self, name: str, hp: int, level: int, mana: int):
        super().__init__(name, hp, level)
        self.mana = mana  # Магическая энергия

    # Метод для применения заклинания
    def cast_spell(self, mana_cost: int) -> None:
        if self.mana <= 0 or self.mana < mana_cost:
            print("Не могу колдовать! Мана закончилась! Ааааа!")
            return
        print(f"{self.name} кастует фаербол, затрачивая {mana_cost} маны!")
        self.mana -= mana_cost

    def attack(self) -> None:
        print(f"Маг {self.name} атакует врага магическим кинжалом")

    def defend(self) -> None:
        print(f"Маг {self.name} кастует защитный купол")

Инкапсуляция

Инкапсуляцию можно представить как состав из двух слов "в" "капсуле". Т.е. условно и упрощенно можно привести такой, пример, что когда мы создали класс AbstractCharacter и добавили в него свойства и методы, то все эти характеристики мы инкапсулировали в пределах этого класса.

Как-будто поместили всё в защитную капсулу, как таблетку.

  1. Таким образом мы связали свойства и методы по смыслу, что они относятся к классу Персонаж
  2. Мы можем управлять доступом к свойствам и методам. Где-то приоткрыть капсулу для доступа извне, или наоборот полностью закрыться.
  3. "Приоткрывать" капсулу можно не для всех характеристик сразу, а выборочно для определенных свойств или методов.

В Python существуют три уровня видимости:

  • Public (публичные) — name — доступны всем
  • Protected (защищённые) — _name — доступны классу и его наследникам (соглашение)
  • Private (приватные) — __name — доступны только внутри класса
Python

        self._hp = hp          # Защищённое свойство (одно подчёркивание)

    @abstractmethod
    def attack(self) -> None:
        pass

    @abstractmethod
    def defend(self) -> None:
        pass

    def __str__(self) -> str:
        return f"Имя={self.name}, уровень={self.level}, здоровье={self._hp}"

Полный Private
Отлично! Мы полностью закрыли доступ к свойству hp! Часто это очень нужно и важно скрыть внутреннюю реализацию класса, чтобы ничего не сломать!
Особенность Python: Двойное подчёркивание __hp вызывает name mangling — Python автоматически переименовывает атрибут в _AbstractCharacter__hp, делая его сложнодоступным извне.

Но в данном случае это как-то слишком радикально. Хотелось бы немного гибкости, чтобы можно было посмотреть значения свойства и как-то обработать ситуацию когда кто-то решил присвоить значение ноль

Есть специальные механизмы для работы со свойствами класса

  • Setter - позволяет гибко управлять инициализацией свойства
  • Getter - позволяет гибко управлять доступом к свойству
Python
from abc import ABC, abstractmethod

class AbstractCharacter(ABC):
    def __init__(self, name: str, hp: int, level: int):
        self.name = name
        self.level = level
        self._hp = hp  # Приватное свойство

    # Геттер для доступа к закрытому полю
    @property
    def hp(self) -> int:
        return self._hp

    # Сеттер для изменения закрытого поля
    @hp.setter
    def hp(self, value: int) -> None:
        if value <= 0:
            print("Здоровье не может быть отрицательным!")
            print("И обнулять тоже читерство! :)")
            return
        else:
            self._hp = value

    @abstractmethod
    def attack(self) -> None:
        pass

    @abstractmethod
    def defend(self) -> None:
        pass

    def __str__(self) -> str:
        return f"Имя={self.name}, уровень={self.level}, здоровье={self._hp}"

class Character:
    def __init__(self, name: str, hp: int):
        self.name = name
        self._hp = hp
        self._max_hp = hp

    @property
    def hp(self) -> int:
        return self._hp

    @hp.setter
    def hp(self, value: int) -> None:
        if value < 0:
            self._hp = 0
        elif value > self._max_hp:
            self._hp = self._max_hp
            print(f"HP не может превышать максимум: {self._max_hp}")
        else:
            self._hp = value

    @property
    def is_alive(self) -> bool:
        """Только геттер — вычисляемое свойство"""
        return self._hp > 0

    @property
    def hp_percentage(self) -> float:
        """Процент здоровья"""
        return (self._hp / self._max_hp) * 100

Полиморфизм

Полиморфизм можно разбить на два слова: "поли" — много, "морфизм" — форм. Это позволяет одному и тому же коду принимать множество форм и вести себя по-разному в зависимости от ситуации.

Чтобы понять, зачем это нужно, давай начнём с примера. Вернёмся к нашим игровым персонажам. Мы создали базовый класс AbstractCharacter, но нам нужно, чтобы у разных классов-наследников (например, воинов, магов и лучников) были свои уникальные способности.

def main():
    knight = Warrior("Рыцарь", 50)  # Создаём рыцаря
    wizard = Mage("Маг", 30)        # Создаём мага
    rogue = "Разбойник"

    # Представим, что мы собираем их в команду
    team = [knight, wizard, rogue]

    for character in team:
        # Проверяем, кто именно находится в команде
        if isinstance(character, Warrior):
            # Если рыцарь, вызываем `attack()` рыцаря
            character.attack() 
        elif isinstance(character, Mage):
            # Если маг, вызываем `attack()` мага
            character.attack() 
        else:
            print("Неизвестный персонаж в команде!")

if __name__ == "__main__":
    main()

Это простой пример, где можно сразу заметить ошибку до выполнения кода, но в реальном приложении это будет уже проблематично! У нас не будет гарантии, например, что все объекты которые мы обрабатываем будут иметь вызываемые методы! Эту проблему в данном случае решает абстрактный класс, который предоставляет одинаковый интерфейс для взаимодействия между всеми объектами.

  • У абстрактного класса Персонаж есть метод attack()
  • Все другие классы которые являются потомками абстрактного класса Персонаж, гарантированно имеют методы attack()
  • И самое главное реализация (форма) этих методов будет уникальная. Один метод attack(), но множество форм его реализации - Полиморфизм

Повторим код теперь с применением полиморфизма

Мы определяем базовый класс с методом attack()

Python
from abc import ABC, abstractmethod

class AbstractCharacter(ABC):
    def __init__(self, name: str, hp: int, level: int):
        self.name = name
        self.level = level
        self.hp = hp

    @abstractmethod
    def attack(self) -> None:
        pass  # Абстрактный метод — каждая реализация своя!

А теперь у каждого потомка этого класса будет своя реализация метода attack()

Python
class Warrior(AbstractCharacter):
    def __init__(self, name: str, hp: int, level: int, strength: int):
        super().__init__(name, hp, level)
        self.strength = strength

    def attack(self) -> None:
        print(f"{self.name} атакует мечом! Урон: {self.strength * self.level}")

class Mage(AbstractCharacter):
    def __init__(self, name: str, hp: int, level: int, mana: int):
        super().__init__(name, hp, level)
        self.mana = mana

    def attack(self) -> None:
        print(f"{self.name} использует заклинание! Магическая сила: {self.mana * self.level}")

Теперь всё гораздо проще. Мы можем собрать всех персонажей в общий список и использовать один вызов attack() для всех:

Python
from typing import List
from character import AbstractCharacter, Warrior, Mage

def main():
    team: List[AbstractCharacter] = [
        Warrior("Рыцарь", 100, 50, 20),
        Mage("Маг", 80, 30, 50),
        Warrior("Паладин", 120, 70, 25),
    ]

    # Полиморфизм в действии:
    for character in team:
        character.attack()  # Вызовется своя реализация у каждого!

if __name__ == "__main__":
    main()

Гарантия и Гибкость работы
Указание типа AbstractCharacter гарантирует, что будут использоваться только те объекты у которых есть нужный метод attack()

Если мы добавим нового наследника (например, лучника), он автоматически подхватится:

Python
class Archer(AbstractCharacter):
    def __init__(self, name: str, hp: int, level: int, agility: int):
        super().__init__(name, hp, level)
        self.agility = agility

    def attack(self) -> None:
        print(f"{self.name} стреляет из лука с точностью {self.agility}!")

Просто добавь его в список team, и всё будет работать:

Python
from typing import List
from character import AbstractCharacter, Warrior, Mage, Archer

def main():
    team: List[AbstractCharacter] = [
        Warrior("Рыцарь", 100, 50, 20),
        Mage("Маг", 80, 30, 50),
        Warrior("Паладин", 120, 70, 25),
    ]

    ranger = Archer("Лучник", 40, 100, 100)
    team.append(ranger)

    # Полиморфизм в действии:
    for character in team:
        character.attack()  # Вызовется своя реализация у каждого!

if __name__ == "__main__":
    main()

Рыцарь атакует мечом! Урон: 1000
Маг использует заклинание! Магическая сила: 1500
Паладин атакует мечом! Урон: 1750
Лучник стреляет из лука с точностью 100!

Duck Typing

Python поддерживает "утиную типизацию" — "Если это выглядит как утка и крякает как утка, то это утка"

Python
class Duck:
    def quack(self) -> None:
        print("Кря!")

class Robot:
    def quack(self) -> None:
        print("Звук кряканья из динамика!")

def make_it_quack(duck_like):
    duck_like.quack()  # Неважно, что это за объект

# Оба объекта "ведут себя как утки"
real_duck = Duck()
robot_duck = Robot()

make_it_quack(real_duck)  # Кря!
make_it_quack(robot_duck) # Звук кряканья из динамика!

Множественное наследование и полиморфизм

Python
from abc import ABC, abstractmethod

class Flyable(ABC):
    @abstractmethod
    def fly(self) -> None:
        pass

class Swimmable(ABC):
    @abstractmethod  
    def swim(self) -> None:
        pass

class Dragon(AbstractCharacter, Flyable):
    def __init__(self, name: str, hp: int, level: int, fire_power: int):
        super().__init__(name, hp, level)
        self.fire_power = fire_power

    def attack(self) -> None:
        print(f"{self.name} дышит огнём! Урон: {self.fire_power}")

    def fly(self) -> None:
        print(f"{self.name} парит в небесах!")

# Использование
dragon = Dragon("Смауг", 1000, 100, 500)
dragon.attack()  # Полиморфизм от AbstractCharacter
dragon.fly()     # Полиморфизм от Flyable

Эти особенности делают Python очень гибким для полиморфизма и позволяют создавать выразительные объектно-ориентированные программы.
