Урок 17. Python ООП. Часть 3 — Интерфейсы

Интерфейсы: использование и отличие от абстрактного класса

Итак, мы уже знаем, что полиморфизм позволяет работать с объектами разных классов, используя общий интерфейс или базовый класс. Но что, если нам нужно, чтобы класс не только "наследовал", но и "обязывался" реализовывать определённые методы, независимо от иерархии? Здесь в дело вступает интерфейс.

Что такое интерфейс?

Интерфейс — это набор "контрактов" (методов и свойств), которые обязуется реализовать класс, подключающийся к интерфейсу. В Python интерфейсы можно реализовать несколькими способами.

Сравним это с абстрактным классом:

  • Абстрактный класс предоставляет как контракт, так и готовую реализацию некоторых методов или свойств. Классы, наследующие абстрактный класс, могут переопределять их.
  • Интерфейс — это чистый контракт. Он диктует, какие методы и свойства должен реализовать класс, но сам не содержит их реализации.

Способы реализации интерфейсов в Python

Python предоставляет несколько способов создания интерфейсов:

  1. ABC (Abstract Base Classes) - формальные интерфейсы
  2. Protocol - структурная типизация (Python 3.8+)
  3. Duck Typing - неформальные интерфейсы

Пример абстрактного класса и интерфейса

Создадим абстрактный класс AbstractCharacter, как мы делали раньше:

Python
from abc import ABC, abstractmethod

class AbstractCharacter(ABC):
    def __init__(self, name: str, level: int):
        self.name = name
        self.level = level

    @abstractmethod
    def attack(self) -> None:
        """Абстрактный метод атаки"""
        pass
    
    def level_up(self) -> None:
        """Реализованный метод"""
        self.level += 1
        print(f"{self.name} повышает уровень до {self.level}!")

Способ 1: Интерфейсы через ABC

Python
from abc import ABC, abstractmethod

class IAttackable(ABC):
    """Интерфейс для объектов, которые могут атаковать"""
    
    @abstractmethod
    def attack(self) -> None:
        """Метод атаки"""
        pass

class IHealable(ABC):
    """Интерфейс для объектов, которые могут лечить"""
    
    @abstractmethod
    def heal(self) -> None:
        """Метод лечения"""
        pass

Разберём отличия:

  1. Абстрактный класс позволяет задать общую базу для всех наследников.
  2. Интерфейс лишь говорит: "Я ожидаю, что у вас будет метод attack()." Никакой реализации он не предоставляет.

Способ 2: Protocol (структурная типизация)

Python
from typing import Protocol

class Attackable(Protocol):
    """Протокол для объектов, которые могут атаковать"""
    
    def attack(self) -> None:
        """Метод атаки"""
        ...

class Healable(Protocol):
    """Протокол для объектов, которые могут лечить"""
    
    def heal(self) -> None:
        """Метод лечения"""
        ...

Особенности Protocol:

  • Не требует явного наследования
  • Работает по принципу "структурной совместимости"
  • Объект соответствует протоколу, если у него есть нужные методы
  • Используется в основном для type checking

Способ 3: Duck Typing (неформальные интерфейсы)

Python
# Простой класс без явного интерфейса
class SimpleWarrior:
    def attack(self) -> None:
        print("Воин атакует!")

class SimpleMage:
    def attack(self) -> None:
        print("Маг кастует заклинание!")
    
    def heal(self) -> None:
        print("Маг лечит!")

# Функция принимает любой объект с методом attack
def make_attack(attacker):
    attacker.attack()  # "Если выглядит как атакующий и атакует как атакующий..."

# Работает с любыми объектами, у которых есть метод attack
make_attack(SimpleWarrior())  # Воин атакует!
make_attack(SimpleMage())     # Маг кастует заклинание!

Когда использовать абстрактный класс, а когда интерфейс?

Абстрактный класс Интерфейс (ABC) Protocol
Используется для объектов с общей базой иерархии (например, персонажи игры, у которых есть общие свойства, такие как name и level). Используется для объектов, которые не обязательно имеют общую базу, но должны соблюдать определённый контракт. Используется для type hints и статической проверки типов.
Может включать как абстрактные методы, так и готовую реализацию. Не содержит реализации — только контракт. Определяет структуру без принуждения к наследованию.
Позволяет избегать дублирования кода. Гарантирует, что класс реализует обязательные методы. Гибкая типизация для существующего кода.

Полиморфизм с интерфейсами

Python
from abc import ABC, abstractmethod

class IAttackable(ABC):
    @abstractmethod
    def attack(self) -> None:
        pass

class IHealable(ABC):
    @abstractmethod
    def heal(self) -> None:
        pass

# Воин реализует интерфейс IAttackable
# Он обязан теперь создать метод attack
class Warrior(IAttackable):
    def attack(self) -> None:
        print("Рыцарь наносит мощный удар мечом!")

# Маг реализует интерфейсы IAttackable и IHealable
# Он обязан теперь создать методы attack и heal
class Mage(IAttackable, IHealable):
    def attack(self) -> None:
        print("Маг кастует заклинание огня!")

    def heal(self) -> None:
        print("Маг использует заклинание лечения.")

Особенности множественного наследования в Python

Python поддерживает множественное наследование, что позволяет классу наследовать от нескольких интерфейсов одновременно:

Python
class Paladin(IAttackable, IHealable):
    """Паладин может и атаковать, и лечить"""
    
    def attack(self) -> None:
        print("Паладин наносит священный удар!")
    
    def heal(self) -> None:
        print("Паладин исцеляет светом!")

Полиморфизм с интерфейсами на практике

Python
from typing import List

def main():
    # Работаем с объектами, реализующими интерфейсы
    # У них гарантированно доступны методы из интерфейсов

    attackers: List[IAttackable] = [Warrior(), Mage(), Paladin()]
    for character in attackers:
        character.attack()
        # Гарантированно вызовется для каждого элемента списка

    print()

    # Только те, кто может лечить
    healers: List[IHealable] = [Mage(), Paladin()]
    # Warrior() здесь нельзя добавить - он не реализует IHealable
    for healer in healers:
        healer.heal()

if __name__ == "__main__":
    main()

Рыцарь наносит мощный удар мечом!
Маг кастует заклинание огня!
Паладин наносит священный удар!

Маг использует заклинание лечения.
Паладин исцеляет светом!

Protocol для type checking

Python
from typing import Protocol, List

class AttackProtocol(Protocol):
    def attack(self) -> None: ...

class HealProtocol(Protocol):
    def heal(self) -> None: ...

# Классы не наследуют от Protocol, но соответствуют его структуре
class Rogue:
    def attack(self) -> None:
        print("Разбойник наносит скрытую атаку!")

class Priest:
    def heal(self) -> None:
        print("Жрец восстанавливает здоровье!")

class Druid:
    def attack(self) -> None:
        print("Друид призывает силы природы!")
    
    def heal(self) -> None:
        print("Друид исцеляет природной магией!")

# Функции с типизацией через Protocol
def perform_attack(attacker: AttackProtocol) -> None:
    attacker.attack()

def perform_healing(healer: HealProtocol) -> None:
    healer.heal()

# Использование
rogue = Rogue()
priest = Priest() 
druid = Druid()

perform_attack(rogue)   # ✓ У Rogue есть метод attack
perform_attack(druid)   # ✓ У Druid есть метод attack
# perform_attack(priest)  # ✗ У Priest нет метода attack

perform_healing(priest) # ✓ У Priest есть метод heal
perform_healing(druid)  # ✓ У Druid есть метод heal
# perform_healing(rogue)  # ✗ У Rogue нет метода heal

Комбинирование подходов

Python
from abc import ABC, abstractmethod
from typing import Protocol, List, Union

# Формальный интерфейс через ABC
class ILivingBeing(ABC):
    @abstractmethod
    def is_alive(self) -> bool:
        pass

# Протокол для структурной типизации
class Movable(Protocol):
    def move(self, distance: int) -> None: ...

# Класс, реализующий ABC и Protocol
class GameCharacter(ILivingBeing):
    def __init__(self, name: str, hp: int):
        self.name = name
        self.hp = hp

    def is_alive(self) -> bool:
        return self.hp > 0
    
    def move(self, distance: int) -> None:
        print(f"{self.name} перемещается на {distance} метров")

# Duck typing класс
class Vehicle:
    def __init__(self, name: str):
        self.name = name
    
    def move(self, distance: int) -> None:
        print(f"{self.name} движется на {distance} км")

# Функция принимает любой объект с методом move
def move_something(movable: Movable, distance: int) -> None:
    movable.move(distance)

# Использование
character = GameCharacter("Герой", 100)
vehicle = Vehicle("Машина")

move_something(character, 10)  # Герой перемещается на 10 метров
move_something(vehicle, 50)    # Машина движется на 50 км

print(character.is_alive())    # True

Продвинутые возможности интерфейсов в Python

1. Регистрация типов как реализации интерфейса

Python
from abc import ABC, abstractmethod

class ISerializable(ABC):
    @abstractmethod
    def serialize(self) -> str:
        pass

# Регистрируем встроенный тип как реализацию интерфейса
ISerializable.register(str)

# Теперь str считается реализацией ISerializable
print(issubclass(str, ISerializable))  # True
print(isinstance("hello", ISerializable))  # True

2. Миксины (Mixins) для расширения функциональности

Python
class LoggerMixin:
    """Миксин для добавления логирования"""
    def log(self, message: str) -> None:
        print(f"[{self.__class__.__name__}] {message}")

class HealthMixin:
    """Миксин для добавления системы здоровья"""
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.max_hp = 100
        self.current_hp = 100
    
    def take_damage(self, damage: int) -> None:
        self.current_hp = max(0, self.current_hp - damage)
        self.log(f"Получен урон {damage}. Здоровье: {self.current_hp}/{self.max_hp}")

class EnhancedWarrior(Warrior, LoggerMixin, HealthMixin):
    """Воин с логированием и системой здоровья"""
    def __init__(self, name: str):
        self.name = name
        super().__init__()
    
    def attack(self) -> None:
        self.log("Атакует мечом!")
        super().attack()

# Использование
warrior = EnhancedWarrior("Конан")
warrior.attack()           # [EnhancedWarrior] Атакует мечом!
                          # Рыцарь наносит мощный удар мечом!
warrior.take_damage(25)   # [EnhancedWarrior] Получен урон 25. Здоровье: 75/100
